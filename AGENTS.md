# AGENTS.md — muxray

Repo constraints from prior work here.

## Hard-won constraints

- **Terminal/pty-driving tests must gate capture on a readiness sentinel that is ordered, echo-invisible, and collision-free — and assert on a definite classified state, not a substring the typed command echo can satisfy.** All three sentinel properties are load-bearing; dropping any one re-introduces the flake: (a) *ordered* — emitted by a command run *after* the content command so capture ordering is guaranteed; (b) *echo-invisible* — a quote-split token (`"foo""bar"`) so it can't match the echoed command line; (c) *collision-free* — a word-free token containing no phrase any program-classifier rule matches. The companion failure is asserting on a substring (`"claude"`) that the command echo already contains, so the test passes before the TUI has rendered. Poll until a *definite status* appears.
- **muxray has TWO independent schema versions — a bump must name which one changed.** `schema.Version` is the JSON *output envelope*; `snapshot.SchemaVersion` is the *on-disk store* format. They bump independently; a blanket "bump schema_version" corrupts the snapshot format. When research recommends a version bump, confirm which schema actually changed against its source file before applying.
- **An output-field rename/add is closed only after a whole-repo grep for the old token across non-Go consumers.** The JSON output contract has readers beyond Go importers: shell scripts that grep the JSON (`scripts/live-drift.sh`), Makefile/CI targets referencing the package path, docs/examples, `--help` strings, and issue-template bodies. The mandatory closure step on any `program`/`status`/field rename or addition is `git grep <old-token>` across `--include=*.{go,md,json,yml,sh}` plus help text — enumerating Go importers alone leaves CI signals and tooling broken.
- **The content-free telemetry allowlist (`TestEventIsContentFree`) is keyed on field names — update it in the same change that renames or adds a field, and marshal an event with *every* field populated so a desync fails loudly.** A rename that leaves the allowlist holding the dead key makes the privacy/no-PII guard vacuously pass. Strengthen the test to populate all fields rather than relying on whatever the default fixture happens to set.
- **Every classification enum value must keep ≥1 fixture (the `TestStatusCoverage` floor); adding a new `program`/`status` value means sweeping the fixture corpus for fixtures the new value now cannibalizes and re-homing them.** A new value (e.g. `shell/idle`) can steal a pane that previously exercised another value (the `generic/unknown` fixture was itself a shell). Also keep a *shared-signal* fixture per candidate — a fixture for program X whose output also contains a phrase program Y matches — so the disambiguation logic is actually exercised, not assumed.
- **Classification symptoms are lifecycle transitions — model the terminal/process lifecycle before enumerating option axes, not just the matched string.** A reported "websocket disconnect classified as agent error" is a *session-lifecycle* event (the harness exits → a shell prompt returns), not an error subtype. Framing the fix as "which error variant?" enforces a false premise; the correct axis is the resulting state (dropped to shell → idle). Trace what the terminal actually does before the AskUserQuestion options are written.
- **Before any outreach/marketing cycle, the advertised install path must run end-to-end from a clean state — a `v*` release must exist and `curl|sh` must succeed.** muxray's primary install is `curl|sh` against a GitHub release; a marketing push with no release is a broken first-use for every evaluator. Make this step 0 of any outreach, and add a `make release-check` target that validates the README curl URL and the documented version against the binary's version constant pre-release.
- **A `-update`-regenerable golden whose expected value is generated from the code under test must be paired with an independent, identity-derived assertion (the fixture's own name/dir/label encodes the expectation).** Otherwise the golden can record a *wrong* answer (a non-representative fixture's output) and pass forever, because regeneration just re-enshrines whatever the code emits. Assert something the fixture's identity forces, not only that output == regenerated-output.
- **Links in GitHub issue/PR template bodies must be absolute URLs or plain-text references — relative `../../` paths do not resolve in rendered issue/comment bodies.** A relative link that works in a repo file view is broken in the rendered issue.
- **A new classifier rule that can fire on ANY pane shape (a global pre-check, a new `program`) must be swept against every real-capture test, not just the `internal/program` unit fixtures — the tmux-backed tests are live consumers of `Detect`.** A shell-prompt pre-check added in `internal/program` broke `internal/tmux/harness_test.go` (and could break `internal/cli/*_test.go`) because those tests capture real panes and the new rule fired on their trailing prompt. Enumerate `internal/tmux/*_test.go` + `internal/cli/*_test.go` as consumers when adding such a rule. Companion: tmux capture tests must render a **held foreground frame** (`printf …; sleep N`) so the footer is deterministic — returning to a shell prompt is timing-flaky *by construction* once shell prompts classify (locally the capture wins the redraw race and passes; CI loses it and goes red). Local `go test ./...` is NOT CI parity for these — observe the live CI run before declaring done. (Instance of the global deterministic-instrumentation rule for wall-clock/timing-sensitive tests.)
- **Never drive muxray (or raw `tmux` session-create/capture) against the DEFAULT tmux server from inside a live tmux+agent session.** Doing so pokes the very pane the agent session runs in and can destabilize or kill the operator's loop. Validate via unit tests with an injected capture/clock seam; run tmux-backed tests with `-short` (skip) locally, or point them at a private `-L <socket>` server — never the default.
- **`internal/program/shell.go` footer recognition is a recurrence hotspot — extend the structural-guard tests, and implement a filed guard when filed (don't defer it).** The `TestShellPrompt_StructuralGuard_*` tests are the brake — extend their dimensions (scrollback ABOVE the prompt, decorated/powerline prompts, chrome BELOW the prompt) rather than adding another ad-hoc branch. The 275-filed structural guard (I3) was deferred and the class then recurred TWICE (280, 281) before it was built — a filed-but-unimplemented structural guard becomes mandatory on first recurrence. The next churn after the guards is the trigger to rearchitect behind a normalize → strip-decoration/chrome → match seam (PUA-folding `undecorate` from 280 is the first piece).
- **The `internal/program/testdata` fixture corpus is a recurring C1-leak surface into PUBLIC_OSS — sanitize personal identifiers by default.** Real terminal captures carry personal `user@host`/paths: a transcript with REPOS.md/LEARN.md agent-meta (272), and `dan@mataf` shipped into a 275 test fixture (caught while sanitizing 280). Fold any real `user@host` to a synthetic form (`dev@host`) when adding a fixture; a pre-commit/CI scan rejecting personal hostnames/emails in `testdata` is the structural guard (filed).
- **Within an adapter's rule set, the live-working-indicator rule must be ordered BEFORE the content-phrase stopped-state rules — footer-bounding does not save a content-substring match because agents render their todo/status panel inside the footer.** A `claude.running` rule keyed on the live `esc to interrupt` chrome must precede `claude.error`/`claude.blocked`, which match phrases like "blocked"/"error" that an agent's own todo-list rows or scrollback can contain incidentally; if the stopped-state rule wins, a live, working pane is misclassified as blocked. This is the "incidental-text-as-state" family (258-I3 `esc to interrupt` cross-provider steal) on the rule-*ordering* axis. The fix is incomplete until the sibling adapters are swept: confirm `codex.go`/`copilot.go` each order their live-working indicator before their content-phrase stopped-state rules, with a regression test per adapter.
